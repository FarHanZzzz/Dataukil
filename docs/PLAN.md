# Ordered implementation and exit gates

The subsequent [33-section master integration](MASTER_COVERAGE.md) and [current validation](MAIN_SYNC_VALIDATION.md) supersede the original scope and exit counts below. Both newer `main` workspaces and the retained local workflows are integrated, with dynamic persisted events and separate backend financial authority.

The subsequent mobile interaction revamp has its own [plan and contract](MOBILE_SIMULATION.md), [AI context](SIMULATION_AI.md), and [actual validation](MOBILE_VALIDATION.md). The historical six gates below describe the initial prototype; the new simulator adds persisted purchase stages and shared case work.

## 1. Contract and fixture foundation
Freeze source capabilities, server-issued demo roles, identities, integer amounts, evidence revisions, four journeys, idempotency/version rules and customer projection. Exit: persisted fixtures and mapped API.

## 2. Deterministic application
Build single-origin FastAPI + SQLite + native accessible HTML/CSS/JS. Customer intake/owned lookup/cases/details; staff queue/source viewer/evidence correction/read-only checks/request/review/handoff/decision/export; separate judge controls. Exit: end-to-end deterministic journey.

## 3. Benchmark before training
Write annotation guide and generator with group-exclusive splits; freeze separately authored exploratory challenge set before selection. Save manifests/hashes. Strong rules baseline and retrieval-only ablation. Exit: data inspection checks. Human independent review remains a real-world validation gate.

## 4. Actual model
Download pinned MIT multilingual E5-small; freeze encoder; train small three-class classifier on claim/passage features. Select settings using development only. Save model/checkpoint hashes, config, labels, source license and raw results. Exit: artifact reload and real inference.

## 5. Integration
Load artifact from disk, bounded input with explicit truncation abstention, exact-reference gates, source status separate. New evidence invalidates analysis and decisions; inference outages use explicitly labelled rules fallback. Exit: current evidence/version/source citations correct.

## 6. Verification and handoff
Meaningful API tests for ownership, authority, repeat requests, concurrency, stale state, repayment, split tender, handoff, GET purity, uploads and unsafe text. Four demo dossiers; browser desktop/mobile checks; actual evaluation limitations, pitch and runbook. Exit: commands/results recorded, running local app, no invented business metrics.

No absolute accuracy or flawless interaction claim will be made. Bugs found by checks will be corrected; unresolved human-data/integration validation will remain explicit.

## Exit status

All six gates completed for the user-confirmed synthetic-only scope: source/API contracts, persistent deterministic journey, frozen synthetic data and baselines, actual trained artifact and error analysis, integrated versioned advisory inference, 46 passing tests and four actual-inference demo dossiers. The first learned model's broader wording performance is poor and is disclosed; rules are primary. Independent human/real-case validation is recorded as future work rather than represented as completed.
